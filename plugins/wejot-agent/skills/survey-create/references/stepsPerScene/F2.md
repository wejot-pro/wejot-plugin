# F2: Change free-mode presentation or interaction

Use this scene when question count and semantics stay unchanged and only layout, animation, pagination, or interaction changes.

- Edit the custom CSS region in `survey-ui.css` and the custom interaction region in `survey-ui.js`.
- Do not insert a new generated question block by hand. A semantic edit requires synchronized JSON and HTML changes through F4.
- Only a standard radio question may auto-advance. Checkbox, scale, matrix, and generic questions require a visible, wired Next action.
- Keep `submitSurvey()` connected to `SurveyDataBridge.submit(buildAnswers(), ...)`. Submit scale scores as numbers.
- Preserve the bridge script, survey and question identity attributes, `buildAnswers()`, `submitSurvey()`, answer state, event bindings, and custom-region markers.
- Before validation, verify that every JS/CSS selector resolves to real HTML, startup leaves a visible screen, and navigation and submission controls are visible and wired.
- For an in-survey ending, read `../submit-stay-pattern.md` and use `submitAndStay`.

```bash
node --check <survey-workspace>/survey-ui.js
python survey-create/scripts/validate_free_mode_survey.py --schema <survey-workspace>/question_schema_generate.json --html <survey-workspace>/survey-unified-generate.html --dir <survey-workspace>
```
