# F1: Create or fully refresh a free-mode survey

Use this scene for free mode, or for a new survey that requires custom layout, interaction, or DOM.

## Workflow

1. Before writing the spec, identify explicit branching, termination, visibility, exclusivity, dynamic candidates, cross-question references, and derived answers. If present, use `survey-logic` and maintain a durable TODO. Do not mistake ordinary free-mode pagination for business logic.
2. Create `survey_spec.json` from `../minimal_survey_spec.json`. Use one `questions` array. Read the example only for structure. For `GENERIC`, include the complete contract and relevant component rule.
3. Generate the skeleton:

   ```bash
   python generate_free_mode_skeleton.py --spec <survey-workspace>/survey_spec.json --output-dir <survey-workspace> --locale <respondent-locale>
   ```

   Add `--force` only when intentionally replacing an existing HTML skeleton after preserving custom CSS and JS.

4. Complete `survey-ui.css` and the custom interaction region of `survey-ui.js`. The generator does not inject `genericHtml`, `genericScript`, or `genericStyle`; implement them in the generic container and custom asset regions.
5. Add visible and distinguishable styles for every question type present. Keep `[data-option]`, `[data-scale-value]`, matrix rows, inputs, upload controls, and generic controls usable in all states.
6. Add a visible submission entry point. Preserve `buildAnswers()`, `submitSurvey()`, the answer bootstrap, the bridge script, question identity attributes, the external CSS/JS links, and the question insertion marker.
7. For one-question-per-page experiences, only standard radio questions may advance immediately after selection. Checkbox, scale, matrix, and multi-step generic questions require a visible, wired Next action. Use `display: none` plus an active state; keep navigation above cards and clickable.
8. If an in-survey ending, result, or poster must remain visible after persistence, read `../submit-stay-pattern.md` and use `submitAndStay`. Do not submit with redirect and then attempt to render the ending.
9. Free mode restores answers on the same device by default, but not necessarily the page. Use `notifyFreeDraftPage(n)` and `window.onFreeDraftPageRestore` only when page restoration is required. Set `window.SURVEY_FREE_ANSWER_DRAFT_DEFAULT = false` to disable drafts.
10. Complete every survey-logic TODO, synchronize header-image metadata and HTML if applicable, and manually verify HTML/CSS/JS selectors, startup visibility, navigation, and submission.
11. Validate:

   ```bash
   python validate_free_mode_survey.py --schema <survey-workspace>/question_schema_generate.json --html <survey-workspace>/survey-unified-generate.html --dir <survey-workspace>
   ```

Validation does not replace runtime inspection. Only submit artifacts when the user explicitly requests submission.
